Better Paseo puts every agent on a Tasks board, on phone, iPad and desktop. When the Paseo client knows more than one host, the board offers **All hosts** alongside the current daemon's complete Tasks board. All hosts aggregates status lanes from online, configured hosts, labels each card with its source host, and routes Agent opening and permission responses back to that host. A disconnected host is shown as offline, not as zero completed tasks. Search and time-range controls work across loaded cards; the full set of single-daemon filters, server-specific operations, and detailed views remains available when switched to that daemon. It also redraws conversations as compact rows for tool calls, reasoning, replies, prompts, checklists and errors.

Paseo's native `render_ui` GenUI cards keep their native rendering (including streaming, fallbacks and follow-up actions) instead of becoming compact tool-call rows. Other tool calls start collapsed. The timeline offers syntax highlighting, streaming Markdown, block details, previews and copying, including table-cell selection. The Tasks board supports search and filters, agent details, stop and archive actions, permission responses, and manual or model-generated titles. Available actions and selection controls vary by platform and host capabilities.

## All-host Tasks board

The board uses Paseo's client-side `useHosts` / `getPaseoClient(serverId)` capabilities to read only hosts already configured and reachable from this client. It does not require or discover a server-to-server pairing, fetch credentials, or open inbound ports. The all-host view reuses Better Paseo's task cards and applies the current device's card preferences. It keeps host and Agent IDs together when aggregating. The normal per-host board remains available for host-specific Stop, archive/unarchive, in-depth task details, and full conversation search. An older Paseo client without host enumeration continues to show the original single-host board.

## Setup and settings

Paseo 0.14.0 or later is required. No separate service account is needed. Settings control reply rendering, fonts, previews and the Tasks board, including an optional provider, model and prompt for title generation. Mermaid code blocks use Paseo’s diagram renderer after the fence closes or the reply ends. File hyperlinks in enhanced replies open Paseo's native workspace file panel on hosts with the timeline file-link bridge, while keeping the entire reply in Better Paseo's Markdown renderer. On compatible Paseo builds that expose the optional `fileLinks.showMenu` hook, desktop right-click and Android/iOS long-press on links open Paseo's full native URL/file menu without disabling plugin Markdown. On desktop, hover shows the authored link destination. Older builds retain their original link handling. The bridge supports desktop and mobile, including relative paths, encoded names and line anchors. On older hosts the plugin retains its existing reveal/copy behavior; turning off plugin Markdown restores the host's file links for every reply.

## Data access and limits

The plugin reads displayed conversations, tool results, agent metadata and host appearance settings. Syntax highlighting sends displayed code to the daemon. Image previews can read files on the daemon; desktop file links can open files or reveal them in the file manager. Presentation and most board settings are shared by clients connected to the daemon.

When title generation is requested, excerpts of the conversation and the configured prompt are sent to a helper agent. By default it uses the provider, model and thinking level of the card's agent; the selected model is used only when Custom automatic title model is turned on. The helper uses the provider's configured permissions; the instruction not to use tools is not a sandbox. The plugin records recent turn timing, token usage and errors on the daemon and reads provider session files for available running token counts. Some board actions use the Paseo CLI or a local daemon connection and are unavailable when those capabilities are missing.
